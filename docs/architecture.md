# Как устроена установка

Установщик — небольшой shell bootstrap и Python 3 без сторонних Python-библиотек.
Bootstrap скачивает исходники целиком, сохраняет их в `/usr/local/lib/tendvpn`
и создаёт команду `/usr/local/bin/tendvpn`. Интерактивный ввод идёт через терминал,
поэтому команда работает при запуске через `curl | sh`.

## Сервисы и порты

Все компоненты работают в Docker Compose с именем проекта `tendvpn`.

| Компонент | Доступ |
| --- | --- |
| NGINX | Публичные 80/tcp и 443/tcp |
| Xray / нода | Публичный 2053/tcp |
| API панели | С Docker-сети и через `127.0.0.1:3000` на сервере |
| Управляющий API ноды | Только из Docker-сети, 2222/tcp |
| Страница подписки | Только из Docker-сети, 3010/tcp |
| PostgreSQL | Только из Docker-сети |
| Valkey | Unix-сокет в общем Docker volume |

NGINX обслуживает панель, подписку и небольшой сайт на домене ноды.
У NGINX есть два TLS-входа: обычный 443 и `/dev/shm/nginx.sock` с PROXY protocol.
Каталог сокета смонтирован и в NGINX, и в ноду. REALITY направляет fallback
в этот сокет. Поэтому подписка также доступна по HTTPS на 2053.

Первый сертификат выпускается Certbot в standalone-режиме. После запуска NGINX
установщик через `certbot reconfigure` проверяет ACME webroot и сохраняет его для
последующих продлений. Reload NGINX выполняется deploy hook. Дополнительно
создаётся таймер `tendvpn-cert-renew.timer` с запуском два раза в сутки.
Аккаунт ACME регистрируется без email.

## Состояние установки

Настройки и созданные файлы находятся в `/opt/tendvpn`:

- `state.json` — параметры, пароли, ключи и идентификаторы созданных объектов;
- `compose.json` — конфигурация Docker Compose;
- `*.env` — переменные сервисов;
- `nginx.conf` — конфигурация веб-сервера;
- `socket/` — общий каталог Unix-сокета;
- `acme/` — каталог HTTP-01 challenge;
- `backups/` — резервные копии.

Каталог состояния имеет права 700, файлы с секретами — 600. В аргументы процессов
API-токены и private key не передаются. Одновременно может работать одна операция
установщика: для этого используется файловая блокировка.

Для профилей, нод, хостов и сквадов сохраняются UUID; для пользователя — числовой ID.
Если процесс прервался между успешным POST и сохранением UUID, при продолжении
уже созданный объект находится по зарезервированному имени.

Проверки важных параметров защищают от случайной перезаписи ручных изменений.
Если отслеживаемый объект удалён или его настройки отличаются от пресета,
мастер останавливается и просит проверить панель.

## Версии компонентов

| Компонент | Образ |
| --- | --- |
| Панель | `remnawave/backend:3.4.11` |
| Нода | `remnawave/node:3.4.6` |
| Страница подписки | `remnawave/subscription-page:8.0.1` |
| NGINX | `nginx:1.30` |
| PostgreSQL | `postgres:18.6` |
| Valkey | `valkey/valkey:9.1.2-alpine` |

Эта комбинация проверена на Ubuntu 24.04 amd64 17 ноября 2026 года.
Версии заданы в `src/tendvpn/render.py`. Используются теги образов, а не digest.

Запросы API сверены с контрактами Remnawave Backend 3.4.11.
[Документация API](https://docs.rw/api/).
