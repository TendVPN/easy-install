# Проверка перед публикацией ролика

Проводить на отдельном чистом Ubuntu 24.04 VPS с тремя реальными поддоменами.
Локальная проверка не подтверждает фактическую работу контейнеров и VPN.

1. Настроить A-записи panel/sub/node на IPv4 VPS. Удалить AAAA, выключить proxy.
2. Открыть 80, 443, 2053/tcp у провайдера; оставить доступ SSH.
3. Скопировать проект, выполнить `sudo sh ./install.sh --local`, выбрать 1.
4. Убедиться, что установка завершилась после проверок, данные доступны повторно
   через `tendvpn credentials`.
5. В панели проверить профиль TendVPN, порт 2053, target Unix socket, отсутствие
   плейсхолдеров и пробелов в short ID, совпадение serverNames с доменом ноды.
6. Проверить ноду VPN_NODE_1: подключена, выбран созданный профиль и его inbound.
7. Проверить Default: включён inbound VPN_VLESS_TCP_REALITY.
8. Проверить VPN - 1: включён, не скрыт, домен ноды, 2053, привязка к ноде,
   Final mask с fragment length 10-20, packets tlshello, interval 10-20.
9. Проверить MAIN_USER: ACTIVE, Default, срок 31.12.2099, HWID 0, трафик 0.
10. Открыть выведенную ссылку в установленном актуальном Happ, проверить импорт,
    подключение, загрузку сайтов и публичный выходной IP. Проверить Final mask
    в фактически импортированной конфигурации клиента.
11. Из внешней сети проверить, что 2222, 3000, 3001, 5432, 6379 и 3010 закрыты.
12. Перезапустить VPS: проверить nginx.sock, Xray, HTTPS, подписку и VPN в Happ.
13. Повторить пункт 1 меню: UUID объектов, ключи и URL подписки прежние.
14. Проверить резервную копию: `pg_restore --list database.dump`, наличие state/env.
15. Проверить `certbot renew --cert-name tendvpn --dry-run --webroot -w /opt/tendvpn/acme`.
    Dry run использует ACME staging; не форсировать повторные production-выпуски.
16. Проверить таймер: `systemctl list-timers tendvpn-cert-renew.timer`.
17. Проверить продолжение после прерывания установки на отдельном новом VPS.
18. После прогона закрепить рабочие версии и записать тестовый результат в README.

Из известных ограничений: нет интерактивного восстановления, изменения доменов,
автоматического отката БД, установки отдельных компонентов и дополнительных VPS-модулей.
Снимки экрана и логи для публикации должны скрывать пароли, ключи и URL подписки.
