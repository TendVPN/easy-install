# TendVPN Easy

[![Проверки](https://github.com/TendVPN/easy-install/actions/workflows/check.yml/badge.svg)](https://github.com/TendVPN/easy-install/actions/workflows/check.yml)
[![Ubuntu 24.04](https://img.shields.io/badge/Ubuntu-24.04-E95420?logo=ubuntu&logoColor=white)](#что-понадобится)
[![MIT](https://img.shields.io/badge/license-MIT-blue)](LICENSE)

Свой VPN на одном VPS: панель Remnawave, нода и страница подписки.
Запускаешь скрипт, вводишь домены и получаешь ссылку для подключения в Happ.
Профиль, ноду, хост и пользователя вручную создавать не нужно.

После установки скрипт остаётся на сервере как команда `tendvpn`. Через неё можно
посмотреть доступы, обновить компоненты, сделать резервную копию и проверить сертификаты.

## Что понадобится

- **Чистый VPS с Ubuntu 24.04** и доступом root по SSH.
- **Домен** и возможность добавить DNS-записи.
- Открытые порты **80, 443 и 2053/tcp** в настройках VPS у хостинг-провайдера.

Создай три A-записи с IP своего сервера:

| Для чего | Пример | Значение |
| --- | --- | --- |
| Панель | `panel.example.com` | IP твоего VPS |
| Подписка | `sub.example.com` | IP твоего VPS |
| Нода | `node.example.com` | IP твоего VPS |

Все три домена должны различаться. Если используешь Cloudflare, выбери **DNS only**
(серое облако). Для этой установки не добавляй AAAA-записи.

Проверено на amd64. Для arm64 предусмотрена установка, но на реальном сервере
эта архитектура пока не тестировалась.

## Установка

Подключись к VPS от root и выполни:

```sh
curl -fsSL https://raw.githubusercontent.com/TendVPN/easy-install/main/install.sh | sh
```

В меню выбери **1. Установить панель + ноду + страницу подписки**.
Мастер попросит домены панели, подписки и ноды, проверит DNS и покажет план установки.
Email для сертификата вводить не нужно.

Если на сервере нет `curl` или Python 3:

```sh
apt update && apt install -y curl python3
```

В конце появятся адрес панели, логин, сгенерированный пароль и ссылка подписки:

```text
Панель: https://panel.example.com
Логин: admin
Пароль: …

Подписка MAIN_USER: https://sub.example.com/…
Добавить в Happ: happ://add/https://sub.example.com/…
Запасная подписка (HTTPS на 2053): https://sub.example.com:2053/…
```

Импортируй подписку в Happ. Если обычная ссылка не открывается из твоей сети,
попробуй запасную с `:2053`. Это та же подписка через другой HTTPS-вход.
Ссылка даёт доступ к VPN — не публикуй её вместе со скриншотами или логами.

Потерял данные? На сервере выполни:

```sh
tendvpn credentials
```

## Что будет настроено

| Объект | Настройки |
| --- | --- |
| Профиль | `TendVPN`, VLESS TCP REALITY на **2053** |
| Нода | `VPN_NODE_1`, сразу подключена к панели |
| Хост | `VPN - 1`, адрес — домен ноды |
| Сквад | `Default`, с inbound созданного профиля |
| Пользователь | `MAIN_USER`, подписка до **31 декабря 2099 года** |
| Лимиты | Без лимита трафика и количества устройств |

Ключи REALITY и short ID генерируются при установке. Используется fingerprint
`firefox`. На хосте задан Final mask: TCP fragment, `tlshello`, длина и интервал
`10-20`. В серверном профиле предусмотрены блокировки почтовых портов, BitTorrent
и обращений к приватным IP. Полный пресет — в [profile.py](src/tendvpn/profile.py).

Сертификат Let's Encrypt выпускается на все три домена и продлевается автоматически.
SSH-порт и настройки входа скрипт не меняет.

## Управление сервером

```sh
tendvpn              # Открыть меню
tendvpn status       # Состояние компонентов
tendvpn credentials  # Данные панели и ссылки подписки
tendvpn backup       # Резервная копия базы и настроек
tendvpn renew        # Проверить, пора ли продлевать сертификат
tendvpn update       # Применить версии компонентов из текущего релиза
tendvpn diagnose     # Состояние и последние логи
tendvpn remove       # Удалить контейнеры, сохранив данные
```

Если установка прервалась, запусти `tendvpn install` ещё раз. Мастер продолжит работу
с сохранёнными настройками. После завершённой установки повторный запуск покажет
доступы; новые ноды, пользователи и ключи создаваться не будут.

Перед обновлением скрипт делает резервную копию. Команда `update` использует версии,
закреплённые в установленном коде. Чтобы обновить сам установщик, повтори команду
установки из нового релиза.

Подробнее: [обновление, копии и удаление](docs/maintenance.md).
